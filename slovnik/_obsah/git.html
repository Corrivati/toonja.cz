Krátká odpověď

Git je systém pro správu verzí. Pamatuje si každou změnu v souborech projektu: kdo ji udělal, kdy a proč. Když se něco pokazí, vrátíte se k fungující verzi jedním krokem. Vytvořil ho Linus Torvalds v roce 2005 pro vývoj Linuxu a dnes na něm stojí většina softwaru na světě.

Git jednoduše: tlačítko Zpět pro celý projekt

Znáte soubor web_final_v3_TED_UZ_OPRAVDU.html? Tak přesně tohle Git řeší.

Místo kopií souborů ukládáte stavy projektu. Každý uložený stav má krátký popis, třeba „oprava odkazu v patičce“. Kdykoli se k němu můžete vrátit, porovnat ho s dneškem nebo zjistit, kdo co změnil. Nic se neztratí.

Jak Git funguje

Stačí znát čtyři slova:

  1. Repozitář. Složka projektu, kterou Git hlídá. Na GitHubu ji máte i online.
  2. Commit. Uložený stav s popisem. Fotka projektu v jednom okamžiku.
  3. Větev. Paralelní verze projektu. Novinku zkoušíte bokem a hlavní verze mezitím běží dál.
  4. Push. Odeslání commitů z počítače na GitHub. Teprve pak je vidí ostatní a hosting.

Když je větev hotová, sloučíte ji s hlavní verzí. U webu to často znamená, že se změna rovnou publikuje.

Z praxe: web v Gitu

Když jsem stěhoval toonja.cz z Webflow, celý web skončil v Git repozitáři na GitHubu. Každá úprava textu má svůj commit a já vidím historii webu řádek po řádku.

Tenhle slovník vznikal v samostatné větvi. Živý web o něm nevěděl, dokud jsem neschválil design. Kdyby se mi nelíbil, větev prostě zahodím a nikdo nic nepozná.

Git je taky důvod, proč může web upravovat AI. Přes MCP do repozitáře sáhne, udělá commit a já ho před zveřejněním zkontroluju. Víc v článku WordPress a Webflow odzvonilo.

Na co si dát pozor

  • Hesla a klíče do Gitu nepatří. Co jednou commitnete, zůstane v historii, i když to později smažete.
  • Bez pushe to není záloha. Repozitář jen ve vašem počítači odejde spolu s diskem.
  • Pište srozumitelné popisy commitů. „Úpravy“ vám za půl roku nic neřekne. „Nový termín workshopu v prosinci“ ano.
  • Velká videa radši jinam. Git je stavěný na text a menší obrázky.
