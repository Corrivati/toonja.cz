Krátká odpověď

Headless CMS je redakční systém, který jen spravuje obsah a nemá vlastní šablony ani vzhled webu. Obsah předává webu, aplikaci nebo jinému kanálu, který ho zobrazí po svém. Často se kombinuje se statickým webem: editor dostane pohodlnou administraci a web zůstane rychlý a bezpečný.

Headless CMS jednoduše

Klasický CMS jako WordPress je restaurace s vlastní kuchyní i jídelnou. Headless CMS je jen kuchyně. Jídlo rozváží, kam si řeknete: na web, do mobilní aplikace, do newsletteru.

Dva hlavní typy

  1. Git-based. Obsah ukládá jako soubory přímo do Git repozitáře. Editor kliká v administraci, na pozadí vznikají commity. Příklady: Decap CMS, TinaCMS.
  2. API-based. Obsah žije v cloudové databázi poskytovatele a web si ho stahuje přes API. Příklady: Contentful, Sanity, Strapi.

Pro malé a střední weby bývá Git-based varianta jednodušší. Obsah zůstává v repozitáři, nic se neplatí za databázi a web je pořád statický.

Příklad: kdy dává smysl

V článku WordPress a Webflow odzvonilo doporučuju headless CMS jako řešení pro jeden konkrétní případ: web, kam denně publikuje redakce nebo netechnický tým.

Malý web, který upravuje jeden člověk, se bez něj obejde. Zadání napíše AI asistentovi a ten upraví soubory v Gitu. Jakmile ale publikuje pět lidí, kteří nechtějí psát zadání, je editor s náhledem a schvalováním k nezaplacení. Obsah přitom pořád leží v repozitáři, ne v cizím systému.

Na co si dát pozor

  • Někdo musí napojit web. Headless CMS nedodá hotové stránky, jen data.
  • Náhled před publikací. Ne všechny systémy umí ukázat, jak bude obsah na webu vypadat. Pro redakci je to zásadní.
  • Vendor lock-in u API systémů. Ověřte si, jak dostanete obsah ven, než se upíšete.
Mára říká

Headless CMS je dobrá odpověď na otázku „kdo bude web upravovat, když ne já“. Pokud odpověď zní „já“, nepotřebujete ho.
